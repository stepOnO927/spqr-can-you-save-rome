## Reproduction and verification

B01: In cloud Chromium, override `window.localStorage` and `window.sessionStorage` getters to throw `SecurityError`. Start, advance, save, and inspect the session-only notice in each entry. B03–B05: use real `tap()` at 640×360, without forced clicks. B06–B07: run `npm test` in a cloud runner. The [browser](../.github/workflows/browser-smoke.yml), [fast](../.github/workflows/spqr-quality.yml) and [Poki](../.github/workflows/poki-release.yml) workflows are release gates; a later failing run supersedes earlier passing evidence.

## Verifiable case details

**B01 — Browser storage denial (P0; persistence/startup).** Current boundary: [`createStore`](../safe-storage.js#L3). Expected: a private-window campaign starts and keeps a usable current-session save. Actual before repair: a thrown storage getter interrupted boot. Reproduce in cloud Chromium by overriding both storage getters with `SecurityError`, then opening each of Roman, Han and atlas. Root cause: startup assumed storage APIs were always accessible. The correction catches access failure, retains an in-memory copy and displays a session-only warning. Regression: [three-entry blocked-storage smoke](../tools/storage-fallback-smoke.mjs). Confidence: **high**, browser reproduction and passing later targeted run. No claim of persistence across a closed private session.

**B02 — Poki package external dependency and lifecycle failure (P0; distribution).** Current packaging boundary: [runtime selection](../scripts/build-poki.mjs#L8) and [SDK bridge](../poki-bridge.js). Expected: the submitted archive serves its own assets and sends Poki gameplay events. Actual source build: public pages loaded analytics, fonts, third-party map code and terrain requests and lacked the platform bridge. Reproduce by serving the public entry points with all non-SDK external requests blocked and inspecting the network/SDK log. Root cause: the public GitHub Pages build was previously the only distribution path. The correction makes a dedicated local-asset package with an honestly labeled offline atlas. Regression: [package smoke](../tools/poki-build-smoke.mjs) validates three entries, event order and zero unauthorized requests. Confidence: **high** for the tested archive, **limited** for official platform acceptance.

**B03 — Advance outside a short frame (P1; Roman mobile UI).** Current correction: [short landscape rules](../style.css#L74) and [640px override](../style.css#L77). Expected: Advance fits inside a 640×360 game frame and accepts a real tap. Actual: the header inherited a 76px minimum and pushed the command below the frame. Reproduce with a 640×360 touch viewport and measure `#step.getBoundingClientRect().bottom`. Root cause: overlapping responsive declarations. Regression: [mobile smoke](../tools/poki-mobile-smoke.mjs), plus [package smoke](../tools/poki-build-smoke.mjs). Confidence: **high** for tested dimensions.

**B04 — Han river intercepts territory tap (P1; Han map).** Current correction: [decorative river rule](../han/han-map.css#L26). Expected: touching Chang’an selects its territory. Actual: a river SVG path above the province intercepted the pointer. Reproduce by tapping `#map path.territory[data-region="changan"]` with Playwright `tap()` rather than a forced click. Root cause: the decorative layer accepted pointer events. Regression: [mobile smoke](../tools/poki-mobile-smoke.mjs). Confidence: **high** for the tested province.

**B05 — Transfer shortcut intercepts Advance (P1; Roman mobile UI).** Current correction: [save-control mounting](../save-transfer.js#L58) and [static button style](../save-transfer.css#L1). Expected: Advance receives its tap. Actual: the merged Transfer Saves control covered the button at 640×360. Reproduce by tapping `#step` in the built package. Root cause: fixed-position control at the same bottom-right location. Regression: [package smoke](../tools/poki-build-smoke.mjs). Confidence: **high** for tested frame sizes.

**B06 — Shared module cache identities diverge (P2; atlas/diagnostics).** Current correction: [atlas import](../map-lab/lab.js#L43) and [Inspector imports](../inspector-ui.js). Expected: shared engine and event modules resolve with the same version string in every entry. Actual: merged branches introduced different `?v=` strings, creating separate browser module identities. Reproduce with [module version assertion](../test/module-versions.test.js) at the failing commit. Root cause: manual versioned imports scattered across entrypoints. Regression: the same test in every fast suite. Confidence: **high** for the mismatched declarations; no specific player-visible state loss was proven.

**B07 — Valid Han neutral territory flagged corrupt (P2; startup diagnostics).** Current correction: [owner validation](../inspector-diagnostics.js#L13). Expected: an unclaimed Han frontier with `owner: null` is legal; an unknown non-null owner is fatal. Actual: the first diagnostic rejected both. Reproduce by validating a fresh Han campaign and comparing with the [diagnostic test](../test/inspector-diagnostics.test.js). Root cause: Roman ownership assumptions were applied to Han geography. Regression: fresh Han state, controlled invalid-owner fixture and restored state. Confidence: **high**.

**B08 — Save smoke asserted a hidden feedback node (P3; test harness only).** Current assertion: [storage smoke](../tools/storage-fallback-smoke.mjs#L24). Expected: after Save closes the menu, the visible toast confirms the action. Actual test read a hidden menu feedback node and failed even though Save completed. Reproduce with the earlier failing workflow. Root cause: test selector no longer matched the save UI lifecycle. Regression: the three-entry blocked-storage smoke. Confidence: **high**. This was a false test failure, not a player-facing save failure.

**B09 — Atlas systems smoke expected failure after storage denial (P3; test harness only).** Current assertion: [systems smoke](../tools/systems-smoke.mjs). Expected under the new persistence contract: quota denial stores a current-session copy and a later read denial can load that copy. Actual old test demanded “cannot save” and “cannot read” messages, causing a false browser-suite failure after the game behaved correctly. Reproduce with [old cloud run 43663570479](https://github.com/stepOnO927/spqr-can-you-save-rome/actions/runs/43663570479). Root cause: stale assertions following the safe-storage repair. The test now checks the session-only warning and successful load. Regression: the full cloud browser workflow. Confidence: **high**.

**B10 — Atlas brief date frozen at January 49 BC (P3; bilingual campaign UI).** Current correction: [atlas control rendering](../map-lab/lab.js#L172). Expected: the campaign brief title uses the current month and year in the chosen language. Actual before repair: its `<span>` contained hard-coded January 49 BC while the turn control advanced. Reproduce by advancing to another month or loading a BCE/CE handoff and reading `.brief .kicker`. Root cause: a static opening-date string remained in the language refresh path. The correction calls the existing `campaignDate` formatter. Regression: [campaign-date browser smoke](../tools/campaign-date-smoke.mjs) checks two dates across the BCE/CE boundary. Confidence: **high** for the source-level defect; cloud browser verification must finish.

**B11 — Atlas and Han omitted Poki load-complete event (P0 for Poki; SDK lifecycle).** Current correction: [Poki bridge](../poki-bridge.js#L7). Expected: each public entry in the dedicated package sends `gameLoadingFinished` before the first `gameplayStart`. Actual before repair: `loaded()` required a populated `#app`, which exists only in Roman; atlas and Han have `#map`. Reproduce with a mock SDK in the built package and inspect the first two events after starting atlas or Han. Root cause: entry-specific root assumption in the shared bridge and incomplete cross-entry assertion. The correction recognizes both shells, and the [package smoke](../tools/poki-build-smoke.mjs) asserts order for all three. Confidence: **high** for the source-level omission; [cloud package run 43664677048](https://github.com/stepOnO927/spqr-can-you-save-rome/actions/runs/43664677048) passed.

**B12 — Safe-save smoke rejected the new storage contract (P3; test harness only).** Current assertion: [safe-save smoke](../tools/safe-save-smoke.mjs). Expected: quota denial retains a current-session save, warns about limited persistence, and permits reload without overwriting a corrupt older slot. Actual old test expected Save and Load to fail, and tried to click a menu that the successful Save had closed. Reproduce by running that script with quota and read methods patched to throw. Root cause: stale expectations after adding the fallback adapter. The corrected script keeps its corrupt-save identity checks and verifies the new save/load behavior. Regression: full browser workflow. Confidence: **high** for the obsolete assertions; cloud result pending.

**B13 — Poki bridge hijacked internal navigation (P1; cross-entry navigation).** Current correction: [external-link handler](../poki-bridge.js#L32). Expected: Han's `../` header link navigates to the Roman root in the package; true external sources go through `PokiSDK.openExternalLink`. Actual before repair: the browser resolves both kinds of anchor to an HTTP URL, so the bridge prevented the internal click and called the SDK stub instead. Reproduce by tapping `header a[href="../"]` from the Han package with a mock SDK that does not navigate. Root cause: the handler checked protocol but not origin. The correction compares URL origins. Regression: [package smoke](../tools/poki-build-smoke.mjs) waits for the real root URL after the tap. Confidence: **high** for the source-level defect; [cloud package run 43668500422](https://github.com/stepOnO927/spqr-can-you-save-rome/actions/runs/43668500422) passed.
